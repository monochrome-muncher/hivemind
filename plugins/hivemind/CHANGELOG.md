# Hivemind agent plugin: what changed for agents, by release

Check this before deciding whether an update matters. "Server" rows take
effect when the Hivemind server is upgraded; "plugin" rows need the plugin
update ([README, Update](README.md#updating)).

| 2.13.0 | **Ranking change on upgrade, with no config change** (ADR 0106, on by default): once an entry has a `helpful` report with a note that is newer than every `stale` or `wrong` report on it (its "last confirmed" date), those flags count at half weight in its quality, so an entry that readers tried and found working after a flag climbs back sooner. A newer flag restores full weight; a bare `helpful` is no confirmation; entries with no flag, or no newer noted helpful, score exactly as before. The quality a `hive_feedback` or `POST /v1/feedback` reply reports uses the same rule, so it stays the number search uses. Tool names, schemas and descriptions are unchanged; the flag backlog, `contested`, the shown correction and every count are unchanged. **Monitoring**: the Grafana dashboard's Namespace variable has no "All" option any more, so it always shows one installation (with two scraped, pool-wide panels showed the larger of the two). **Operators**: no migrations; new setting `HIVEMIND_CONFIRMATION_HALVES_FLAGS` (default `true`; `false` counts every flag in full again, bit for bit); re-import the dashboard if you use it. New `make measure-flags` (a feedback simulation), not part of the server. | Unchanged. | Nothing to refresh. |
| 2.12.2 | Nothing an agent sees changes: the ten tool names, schemas and descriptions are unchanged, and so is search ranking. **Security fix** (low): `PATCH /v1/admin/agents` answers 403 to a non-admin key before looking anything up, so an agent or org key can no longer tell which fleet ids exist from a 404 versus a 403. **Fixes**: a batch read (`hive_get` with `entry_ids`, `POST /v1/entries/get`) returns an entry once when two ids differ only by letter case; `HIVEMIND_LOG_LEVEL` applies even when a logging handler was installed before startup; the MCP server applies `HIVEMIND_REQUIRE_STORED_KEYS` (ADR 0082) to a fixed credential as well as to per-request ones (no shipped runner was affected); `hivemind-keys bootstrap-secret` names the Secret and namespace to delete by hand when a failed run could not clean it up, instead of leaving it quietly; a `hivemind-migrate` rollback that lost its lock connection says so instead of reporting success. The REST routes are built once per process (an app's first request no longer pays ~55 ms; the OpenAPI document is unchanged). **Operators**: no migrations, no new settings. | Unchanged. README and comments only (the incognito launcher takes `kilo`; for Codex it unsets only the key). | Nothing to refresh. |
| 2.12.1 | **`hive_write` `sources` schema is typed** (ADR 0105): `tools/list` now shows each source as `{type, ref}` with `type` one of `path`, `url`, `session`, `other` (both required, no extra keys), matching the REST API and SPEC §4.1, and the `hive_write` description names the field (a URL's `ref` is the URL itself; entry ids go in `see_also`). The server still accepts the same input as before and answers a malformed source with the same `invalid_input` error, so agents stop guessing the shape. **Admin panel and portal**: static files are served with `Cache-Control: no-cache`, so a browser picks up a new release on the next load instead of running a cached old bundle. Search ranking and defaults are unchanged. **Operators**: no migrations, no new settings. New `make measure-longmemeval` (search-only LongMemEval measurement; results in `docs/retrieval-experiments.md`), not part of the server. | Unchanged. | Nothing to refresh. |
| 2.12.0 | Nothing an agent sees changes: the ten tool names, schemas and descriptions are unchanged, and so is search ranking. **Settings removed** (ADR 0103): the off-by-default `HIVEMIND_RECENCY_FROM_CONFIRMATION` (ADR 0071) and `HIVEMIND_RECENCY_BY_KIND` (ADR 0072) measured worse twice and are gone; a server that still has them set starts, ignores them and logs a warning (even with `HIVEMIND_STRICT_ENV=true`). **MCP `/metrics`** (ADR 0104): `hivemind-mcp-http` serves its own request, tool-call and degraded-search series on an unauthenticated `GET /metrics` when `HIVEMIND_MCP_METRICS_ENABLED=true` (off by default, on in the Kubernetes manifest, off in compose), so a Prometheus scrape of the MCP pods no longer gets 401. **Monitoring**: an optional Prometheus Operator ServiceMonitor and a Grafana dashboard under `deploy/kubernetes/optional/monitoring/`. **Operators**: no migrations; `make measure-confirmation` is now `make measure-ranking`. | Unchanged. README wording only (contributors can pin). | Nothing to refresh. |
| 2.11.0 | **Ranking changes on upgrade, with no config change.** **Query instruction** (ADR 0097, on by default): the search query sent to the vector stream is prefixed with an instruction for Qwen3-Embedding (entries and the keyword stream are unchanged); pooled MRR rose from 0.835 to 0.881 on Qwen3-Embedding, while a search worded like an existing entry ranks it a little lower; `HIVEMIND_QUERY_INSTRUCTION=` (empty) turns it off. **Similarity cut-off** (ADR 0100): `HIVEMIND_VECTOR_MIN_SIMILARITY` defaults to 0.45, so an off-topic search comes back empty more often; empty or `none` turns it off. **Recency hint** (ADR 0101): on by default, so a search's `recency` hint (`prefer_recent`, `ignore_age`) is honoured; the `hive_search` description steers timeless questions to `ignore_age`; `HIVEMIND_RECENCY_HINT=false` ignores it. **Catch-up filter** (ADR 0098): `hive_list relied_on_changed: true` (REST `GET /v1/entries?relied_on_changed=true`) lists the entries you rated `helpful` that were since superseded, withdrawn, or reported `stale` or `wrong` by someone else. **`answers_open_question` write warning** (ADR 0099): `hive_write` (and `check: true`) warns when the draft may answer an entry tagged `open-question` or `anomaly` (similarity 0.70 or more); advisory only. **Pins** (ADR 0096): contributors as well as privileged agents pin and unpin (others' pins too), at most 3 pins per agent and 10 per fleet; lurkers cannot; withdrawing an entry unpins it and the briefing leaves withdrawn entries out; the entrypoint applies it, or run `make migrate`); new defaults for `HIVEMIND_QUERY_INSTRUCTION`, `HIVEMIND_VECTOR_MIN_SIMILARITY` (0.45) and `HIVEMIND_RECENCY_HINT` (`true`); a non-Qwen embedder should measure (`make measure-query-instruction`, `make measure-threshold`) or turn the first two off. | The end-of-session reminder also fires after a long session that read entries but rated nothing. The `hivemind` skill: search with the question plus the exact error, filters narrow, hits carry corrections, a weekly `relied_on_changed` catch-up, no hits after one rephrase means a gap (stop and say so), and the open-question remedy. Cline sends the full stay-aware line on a task's first prompt only and a short line after. | Instruction block unchanged. A hand-installed Claude Code hook should copy the new `hivemind-stop.sh`; hand-copied Cline hooks should be copied again. |
| 2.10.0 | **Ranking change:** the author `importance` factor narrows from 0.6–1.0 to 0.9–1.1 (ADR 0088, on by default), so fleet feedback, not the author's own rating, decides between near-equal hits; `HIVEMIND_NARROW_IMPORTANCE=false` restores the old order. **`near_duplicate` write warning** (ADR 0087): `hive_write` (and `check: true`) warns when the nearest related entry has cosine similarity 0.90 or more, naming it; advisory only, entries the draft already links with `see_also` are skipped. **Tool text:** the server instructions say to rate what your work tested (not what you relied on), and the `hive_write` description says to supersede only what an entry fully replaces and link the rest with `see_also`. **Agent portal** (`hivemind-portal`, ADR 0095): a person signs in with one agent's key to see its memories, the verdicts it gave and received, its home fleet's memories and pins, and to search; they can withdraw that agent's own memories with a reason (audited as `entry.withdraw` via portal). Portal searches are not counted in search metrics. **Admin panel** (admin key only): feedback log (ADR 0090), per-agent page (ADR 0091), each fleet's pins (ADR 0092), flag backlog (ADR 0093), CSV export (ADR 0094), and owner-level rating metrics in fleet health (ADR 0089). **Operators**: no migrations; new `HIVEMIND_NARROW_IMPORTANCE` (default `true`) and `HIVEMIND_PORTAL_API_URL` / `HIVEMIND_PORTAL_API_CA_BUNDLE`; upgrade hivemind-api before or with hivemind-admin and hivemind-portal. | **New harnesses: Cline and KiloCode** (setup references, incognito launcher, Cline hooks for the stay-aware line and the end-of-task nudge). **OpenCode v2** plugin API supported alongside v1. **Fixes:** the Claude Code Stop reminder never fired (it read tool definitions in the transcript as calls); the Cline nudge read the wrong tool-name and subagent fields. The `hivemind` skill gains a few words on the `near_duplicate` warning. | Instruction block unchanged. A hand-installed Claude Code hook should copy the new `hivemind-stop.sh`. |
