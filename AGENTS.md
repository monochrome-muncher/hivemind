# AGENTS.md — Hivemind

Hivemind is a shared memory service for an organization's AI agents (one Postgres-backed pool all agents read and write). The repo is spec-first: docs define the system, the code implements it.

## Before doing anything here

Read in this order:

1. [README.md](README.md) — what Hivemind is (short)
2. [SPEC.md](SPEC.md) — the v1 spec; the source of truth for scope and behavior
3. [CONTEXT.md](CONTEXT.md) — the glossary; the source of truth for **terminology**
4. [docs/adr/](docs/adr/) — decisions and their reasons; read the relevant ADR before touching the area it governs
5. [ROADMAP.md](ROADMAP.md) — what to build next, in what order (the living plan; see the §10 trigger-metric definitions)

## Commands

The dev environment is `uv`-managed (Python 3.14); Postgres (with pgvector) runs in docker.

| Task | Command |
|---|---|
| Install deps (creates `.venv`) | `make install` (or `uv sync`) |
| Start Postgres (pgvector, `localhost:5432`, db `hivemind`) | `make pg` |
| Apply DB migrations (ordered chain, advisory-locked; ADR 0020) | `make migrate` (or `uv run hivemind-migrate`) |
| Roll back the last migration (refuses `0001`; ADR 0020) | `make rollback` (or `make rollback N=2`) |
| Regenerate the `schema.sql` reference (generated, never applied) | `make schema-ref` |
| Check expand-and-contract against previous releases (ADR 0020) | `scripts/check-backward-compat.sh` |
| Run unit tests (no Postgres needed) | `make test-unit` (or `uv run pytest tests/unit`) |
| Run the full suite (unit + integration; integration skips if Postgres is down) | `make test` (or `uv run pytest`) — **DESTRUCTIVE: the integration tests `TRUNCATE` `entries`/`credentials` and `DROP SCHEMA` in the database named by `HIVEMIND_DATABASE_URL`** (the same variable `make api`/`make migrate` use). Never export a real DSN here. `tests/conftest.py` refuses names that do not look like dev/test databases (`hivemind`, `hivemind_*`, `*_test`, ...) unless `HM_TEST_ALLOW_ANY_DB=1 (deliberately not `HIVEMIND_`-prefixed: that would trip `HIVEMIND_STRICT_ENV`)`; `scripts/check-backward-compat.sh` is equally destructive |
| Type-check (strict) + lint + format check | `make check` (mypy + ruff) |
| Auto-format + auto-fix | `make format` |
| Run the REST API | `make api` (or `uv run hivemind-api`) |
| Run the MCP server (stdio) | `make mcp` (or `uv run hivemind-mcp`) |
| Run the Postgres-backed MCP runner (per-agent, stdio; ADR 0009) | `make mcp-pg` (or `uv run hivemind-mcp-pg`) |
| Run the hostable streamable-HTTP MCP runner (detached docker service, host port 8088; ADR 0010) | `make mcp-http` (or `docker compose up -d mcp-http`) |
| Stop the mcp-http docker service / run it as a local process | `make mcp-http-down` / `make mcp-http-dev` |
| Stop Postgres / wipe its data | `make pg-down` / `make pg-reset` |

Environment: the service reads `HIVEMIND_*` env vars (see `src/hivemind/config.py`). The dev default is `HIVEMIND_DATABASE_URL=postgresql://hivemind:hivemind@localhost:5432/hivemind`. Embedding knobs: `HIVEMIND_EMBEDDING_ENDPOINT` / `_API_KEY` / `_MODEL` / `_DIM` (ADR 0005).

## Architecture map (where things live)

- `src/hivemind/domain/` — the frozen domain (Entry, EntryDraft, filters, enums) + the access model (`access.py`: TrustLevel, Agent, Fleet, Visibility + the single source-of-truth visibility matrix, ADR 0011). No I/O.
- `src/hivemind/ports.py` — the SEAMS: `Store`, `Embedder`, `Authenticator` protocols + `Credential`. Code against these, never against a concrete adapter.
- `src/hivemind/retrieval/` — the pure retrieval math (RRF fusion, decay-aware scoring, feedback quality) + `eval.py` (the retrieval-quality metrics: hit@k, MRR, nDCG, ROADMAP §1.1). No I/O; unit-tested against hand-computed values.
- `src/hivemind/services/` — the orchestration layer, the deep modules (small interfaces, deep behavior). `search.py` = `SearchService` (hybrid retrieval, SPEC §6); `governance.py` = `WriteService` + `GovernanceService` (write, withdraw, feedback and its readable summary, SPEC §4.1/§4.2, ADR 0051); `chain.py` = `supersession_chain` (the shared `?history` walk, SPEC §5.1/§5.2); `access.py` = `AccessService` (registration + fleet/trust management + `resolve_write_scope`, ADRs 0011–0012); `audit.py` = `record_admin_action` (the app-side audit-log writer, ADR 0027); `metrics.py` = `MetricsService` (the usage counters, ROADMAP §3.3; also served as Prometheus gauges by `api/prometheus.py` at `GET /metrics`, ADR 0050).
- `src/hivemind/memstore.py` — `MemoryStore`: the in-memory reference Store (dev + unit tests).
- `src/hivemind/store/` — `PgStore` + `PgAuthenticator` (asyncpg + pgvector) and the `build_store` / `build_authenticator` factories. `migrations/` is the ordered migration chain (ADR 0020) and the schema's **source of truth**; `migrate.py` applies it under a Postgres advisory lock; `schema.sql` is a GENERATED reference (`make schema-ref`) — never applied, never hand-edited. A shipped migration is frozen (`tests/unit/migration_checksums.txt` pins it); corrections are new migrations.
- `src/hivemind/embeddings/` — `OpenAICompatEmbedder` (the `Embedder` port's production implementation) + the `build_embedder` factory.
- `src/hivemind/api/` — the FastAPI surface (REST §5.1): schemas, deps (auth), routes, main.
- `src/hivemind/mcp/` — the MCP server (eight verbs, §5.2): app, server (stdio dev + per-agent `hivemind-mcp-pg` runners), http (hostable streamable-HTTP runner, ADR 0010), local embedder.
- `tests/unit/` — hermetic unit tests (fakes from `tests/fakes.py`; no Postgres, no network).
- `plugins/hivemind/` — the agent plugin (Claude Code + Codex, marketplaces at `.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json`; also a DeepSeek Harness bundle via `package.json` + `cordis.patch.yml` + `dsh/hivemind-skills.js`, which relies on the MCP server's `instructions` staying in DSH's never-compacted system prompt instead of a hook; also a **Hermes native plugin** — `plugin.yaml` + `__init__.py` — serving the skills and registering a Hivemind system-prompt section (upstream Hermes does not render it, hermes-agent#117432, so the `SOUL.md` block is required); and a **Pi package** — the `pi` key in `package.json` + `extensions/hivemind.ts`, which adds the same system-prompt section on `before_agent_start`): the `hivemind` skill (always-on usage rules), the `hivemind-setup` skill (connect, register, switch to the agent key, stay aware; since 1.2.2 harness-neutral: it first identifies the harness from evidence, never from the model, and every harness-specific instruction lives in `skills/hivemind-setup/references/<harness>.md`, one file per harness, which the drift test keeps routed and complete), a `SessionStart` hook re-injected on startup/resume/clear/compact, and the Claude Code MCP config. `tests/unit/test_agent_plugin.py` keeps its tool names, `hive_whoami` fields, versions and the three stay-aware reminder texts in step with the server. Every version bump adds a row to the plugin README's "What changed for agents, by release" table (server / plugin / the user's own copies); the same test enforces it. Since 1.1.0 (ADRs 0035–0036): incognito sessions (`HIVEMIND_INCOGNITO`, the `bin/hivemind-incognito` launcher, a fixed incognito reminder sentence pinned by the same test, local notes marked `[hivemind: incognito, never upload]`), and the foreign-entry rule for privileged agents (hits carry `scope`/`fleet_id`; use, don't relay). The repository-root `package.json` (`hivemind-agent-plugin`, the same name as `plugins/hivemind/package.json`) exists so the harnesses that install a package from a Git URL — DeepSeek Harness, Pi and OpenCode — can install the plugin from this repository: it points at `plugins/hivemind/cordis.patch.yml` and ships the patch, `dsh/` and `skills/` (the drift test checks its `files` covers what the patch loads). Since 1.2.0 it also covers Oh My Pi (installed through the Claude Code marketplace; the Pi extension handles OMP's prompt shape and blocks Hivemind calls, including its `xd://` routes, in incognito sessions) and OpenCode (`opencode/hivemind.js`: a `config` hook registers the MCP server and skills, `experimental.chat.system.transform` adds the reminder; installed from the Git URL via the root `package.json` `exports["./server"]`). The root manifest also carries the `pi` key, so one Git URL installs Hivemind in DeepSeek Harness, Pi and OpenCode; it deliberately has no `peerDependencies` (pnpm and npm would auto-install the Pi agent). DeepSeek Harness (1.2.1): DSH loads `.env` from the start directory (ranked above `~/.dsh/.env`) and strips `*KEY*`/`*TOKEN*`/`*SECRET*`/`*PASSWORD*` variables from every child process. `cordis.patch.yml` therefore resolves every Hivemind value through one resolver (repeated verbatim per field; a test keeps the copies identical and evaluates them the way DSH's loader does) that ignores the environment when the start directory's `.env` names any `HIVEMIND_*` variable, so a repository cannot redirect the key; the one exception is `HIVEMIND_INCOGNITO`, which is on if the process environment **or** `~/.dsh/.env` says so and can never be turned off by a project `.env`. **Gemini CLI** is supported without a plugin: `references/gemini-cli.md` (MCP entry, skills, `GEMINI.md` block), routed and checked by the drift test. **ADR 0043**: entry content is data written by other agents, never instructions; stated in the server `instructions` and the `hivemind` skill (both pinned by the drift test), with structural markers deferred.
- `tests/eval/` — the retrieval eval harness (ROADMAP §1.1): a committed golden set + a CI gate pinning a floor on hit@k / MRR / nDCG, so retrieval regressions are measured, not vibes. `temporal.py` is a second, **age-varied** fixture (the golden set seeds every entry at one timestamp, so it is blind to the SPEC §6.4 recency term), `temporal_runner.py` is the seeding/ranking machinery its experiments share, and `test_decay_experiment.py` (ROADMAP §4.4, sweeps `half_life_days`; ROADMAP §4.6-(a), sweeps `recency_floor`) + `test_rrf_k_experiment.py` (ROADMAP §4.6, sweeps `rrf_k`) are those experiments. They pin direction and arithmetic (e.g. decay-off beats always-on on this fixture; the fused RRF range is `2(k+20)/(k+1)`; a floor bounds the recency range at `1/floor`, so match quality dominates above `floor > 0.381`), not absolute metric values — measurements, not gates. Every variant is a `SearchConfig` value; the sweeps themselves change no default, and their baselines pass floor-off **explicitly** (the shipped default is now the floored term — ADR 0022).
- `tests/integration/` — Postgres-backed Store tests; they SKIP cleanly when the DB is unreachable.

## Rules

- **Terminology is the glossary.** Use the canonical terms from CONTEXT.md. Say "supersede", never "update" or "overwrite" an entry (entries are immutable — ADR 0001). "Memory date" means `occurred_at`, not `created_at`.
- **Implement what the spec commits to.** v1 scope is SPEC.md §1–§8. The non-goals (§9) are non-goals: no UI, no multi-tenancy, no knowledge graph, no passive capture, no Redis, no sharding. Build the §10 extensions only when their stated trigger fires.
- **Code at the seams.** New data access goes behind the `Store` port; new providers behind `Embedder`; new auth behind `Authenticator`. The services layer is the only orchestrator; the HTTP and MCP layers are thin (validation + auth + error mapping only).
- **TDD at the agreed seams.** Tests live at the seams (`tests/unit/`, `tests/integration/`), never against internals. Red → green, one behavior at a time.
- **Decisions go in ADRs.** A new permanent design choice gets a new `docs/adr/NNNN-slug.md` (next sequential number) + a matching SPEC.md section. A decision contradicting an existing ADR gets a NEW ADR that supersedes it — never a quiet edit of the old one.
- **Glossary stays current.** When a term is resolved (design, review, or implementation), update CONTEXT.md in the same change. CONTEXT.md is a glossary: no implementation details, no prose, no rationale (that's the ADR's job).
- **One source of truth per meaning.** The spec owns behavior; the ADRs own reasons; the glossary owns words. Don't restate spec behavior in the README or docs — link to it.
- **Quality bar:** `make check` (mypy strict + ruff) clean AND `make test` green, before a change is considered done.

## State of this repo

Spec + docs (`README.md`, `SPEC.md`, `CONTEXT.md`, `AGENTS.md`, `CLAUDE.md`, `ROADMAP.md`, `DEPLOY.md`, `config/`, `deploy/kubernetes/`, `.gitlab-ci.yml`, `docs/adr/0001`–`0037` and `0039`–`0057` (`0038` is unused), `docs/ops-runbook.md`, `docs/dogfooding-notes.md`) plus the v1 implementation: domain, ports, retrieval math (RRF fusion, decay scoring, feedback quality + the retrieval-quality metrics in `retrieval/eval.py`), services, in-memory store, Postgres store (asyncpg + pgvector), OpenAI-compatible embedder (with bounded, jittered retries on transient failures under an overall per-call deadline, ADR 0014 as amended by ADR 0041; provider errors are sanitized — never a key or URL in an error or log — via `providers.py`), FastAPI REST surface, and the MCP surface (three runners: stdio dev, per-agent Postgres `hivemind-mcp-pg`, and the hostable streamable-HTTP `hivemind-mcp-http` — shipped as a detached docker-compose service, host port 8088). The default embedding dimension is 1024 (ADR 0015; the dev Makefile pins 512 for fast local vLLM embedding), and `migrate` fails loudly with an actionable error when the pool's dim differs from the configured dim (ADR 0015) — never a silent no-op that later surfaces as a confusing `DataError`. The access-control & fleet model (ADRs 0011–0012, SPEC §12) is implemented end to end: domain (`domain/access.py`: TrustLevel / Agent / Fleet / Visibility + the visibility matrix), the `Store` seam (fleet / agent methods + visibility-aware reads), the v2 key model (org / agent / admin; `user` keys retired) + `AccessService` (register / activate / trust-level / home-fleet / revoke / org-key rotation), the REST surface (`POST /v1/agents` + admin endpoints), the MCP surface (`hive_register` + write-scope + visibility), and the reduced `hivemind-keys` CLI. The retrieval eval harness (`tests/eval/` + `retrieval/eval.py`) reports hit@k / MRR / nDCG on a committed golden set with a CI gate pinning a floor on them. The minimal usage-counters surface (Tier 3.3): `MetricsService` + `GET /v1/metrics` (entries / fleets / agents counters, plus searches and empty searches per fleet since **ADR 0056**, migration `0010.search-counts`). The migration story (ADR 0020, SPEC §8.6, Tier 3.5 — supersedes ADR 0013/Tier 3.2): an ordered migration chain under `src/hivemind/store/migrations/` (yoyo-migrations) with a `.rollback.sql` per step, applied under a **Postgres advisory lock** so concurrent replicas are safe; `current_schema_version` reads `_yoyo_migration` and `schema.sql` is a CI-generated, non-authoritative reference. The chain, the advisory-locked runner, `--rollback`, the generated `schema.sql`, `startupProbe` on both Deployments, and the CI gates (migration-checksum immutability, schema-reference currency, and the previous-releases expand-and-contract check) are all shipped. `0001.initial-schema` reproduces the pre-ADR-0020 schema exactly (verified by `pg_dump` diff). The chain's first two riders on top of `0001` (ROADMAP §4.5): `0002.importance-source` adds `entries.importance_source text NOT NULL DEFAULT 'default'`, recording at every write seam (REST + MCP) whether `importance` was caller-supplied or fell out of the default, surfaced in the §3.3 counters (`by_importance_source`); `0003.importance-source-check` closes the vocabulary gap `0002` left open with a named `entries_importance_source_check` CHECK constraint (`caller`/`default`), matching every other enum-shaped column in the table. `0004.hnsw-vector-index` (ADR 0025, SPEC §6.2, ROADMAP §3.6) adds the chain's first index: an **HNSW** index on `entries.embedding` (`vector_cosine_ops`, `m = 16`, `ef_construction = 64`, built `CONCURRENTLY` under `-- transactional: false`), because `search_vector` previously sequentially scanned every ~4KB embedding in an append-only table. The query-time GUCs (`hnsw.iterative_scan = strict_order`, `hnsw.ef_search = 40`) are **not** schema: they are `SET LOCAL` in `search_vector`'s own transaction, since a transaction-mode PgBouncer discards session state set on connection init. This makes the vector stream **approximate** — a real behaviour change, written up as one: the Postgres-backed measurement (`tests/integration/test_vector_index_recall.py`, the §1.1 golden set on real Postgres, skip-if-down) did **not** confirm parity (hit@5 1.000 exact vs 0.625 at 2k distractors, 0.375 at 20k), and the `ef_search` sweep plateaus below parity, so the loss is graph reachability rather than candidate budget and **nothing was tuned to make it green**. ADR 0025 carries the numbers, the fixture caveat, and the re-measure trigger; `tests/eval/` and its pinned gate are untouched. `0004` also surfaced a latent defect in ADR 0020: a `CREATE INDEX CONCURRENTLY` migration **deadlocks** against the `pg_advisory_lock` that guards the chain (a sibling blocked inside `pg_advisory_lock` holds a virtual xid for the whole wait, which the winner's index build waits on forever; the lock holder is idle, so Postgres's deadlock detector never sees the cycle), so `migrate` now acquires the same lock by **polling `pg_try_advisory_lock`** — unchanged semantics, short transactions, and `test_concurrent_migrators_are_serialised_by_the_advisory_lock` is what caught it (it hung rather than failed). The ops story (Tier 3.1): `docs/ops-runbook.md` (deployment, backups, health, key rotation). The end-to-end dogfood (Tier 1.2) was run with a real agent + real embedder (`docs/dogfooding-notes.md`); it caught one real defect — `hive_write`'s forced `scope="org"` default (in the registered MCP wrapper and the REST schema) rejected every L2/L1 omitted-scope write, bypassing ADR 0011's omitted-scope rule — now fixed at all three seams (app, registered wrapper, REST) and locked by tests, along with empty-`entry_id` guards and `fleet_id` in entry reads. Entity extraction (ADR 0016, SPEC §13 — a pre-staged §10 extension on scale ambition, trigger NOT fired) is implemented end to end: the `Extractor` port (sibling of `Embedder`) + `OpenAICompatExtractor` (`src/hivemind/extractor.py` — ADR 0014 retry pattern, all-or-nothing schema-validated `{name, kind}` facets, `build_extractor` factory; **unset `HIVEMIND_EXTRACTOR_ENDPOINT` = off**, zero LLM cost), schema v6 (`entities jsonb` + `entity_names text[]` GIN + `entities_model`, symmetric with the embedding pair), a best-effort `WriteService` hook (an extraction failure never blocks a write), and the read surface (REST `entities` filter — AND, case-insensitive — + `EntryOut` facets, MCP `hive_search` / `hive_list` + the registered tool wrappers); hermetic tests + a live E2E test (skip-unreachable; dev endpoint `http://localhost:8080/v1` / `qwen3.8-27b`). Graph-expanded retrieval + the canonical entity registry stay trigger-held (Tier 5). The production-deployment story (Kubernetes + GitLab CI/CD) is shipped: a generic single image (runner selected by `HIVEMIND_RUNNER` — api / mcp-http / migrate / keys), a kustomize manifest tree (`deploy/kubernetes/` — ConfigMap + Secret template, two Deployments (migration is owned by the image entrypoint, ADR 0018), optional nginx/cert-manager Ingress with SSE tuning), a GitLab pipeline (`.gitlab-ci.yml` — test on pgvector, docker build/push, deploy via the pre-configured GitLab Kubernetes agent + an idempotent first-run key bootstrap that lands the admin/org keys in the k8s Secret), environment profile files (`config/.env.example` + `ENVIRONMENT` selection, ADR 0017), and the `hivemind-keys revoke-admin` subcommand that completes the admin-key rotation story (DEPLOY.md §5). Unauthenticated orchestrator probe endpoints (ADR 0019): `/mcp/liveness` + `/mcp/health` (shallow readiness; the deep DB check is `/mcp/health/database`, cached ~2 s, ADR 0037/0042) on the mcp-http runner and `/v1/liveness` (shallow) on the REST API, with the static `/v1/health` (SPEC §5.1) unchanged. **ADR 0026 (SPEC §8.2, ROADMAP §3.7) supersedes ADR 0007** — outright, not narrowly: its one-process clause becomes **2 replicas per app-tier runner** (`hivemind-api` and `hivemind-mcp-http`), with an explicit `maxSurge: 1` / `maxUnavailable: 0` rollout and a `minAvailable: 1` PodDisruptionBudget each (the PDB is the part that survives a node drain — `maxUnavailable` governs rollouts, not voluntary disruption), and its docker-compose clause becomes Kubernetes (already true since Tier 3.4, never written down). **One Postgres node, no Redis, no sharding, one organization per deployment are UNCHANGED**, and the ADR rules out multi-tenancy, storage scaling, sharding, read replicas, Redis and throughput-motivated scaling in its own text. The goal is **availability only**: throughput is rejected on the workload's shape (the app tier is I/O-bound on the embedder, extractor and Postgres — more replicas pressure three shared bottlenecks and add capacity to none), AZ tolerance is rejected as uncashable against one Postgres node, and 3 replicas as over-provisioning. Nothing in the app tier needed changing: the REST surface holds no session state, the MCP transport is stateless with per-request credentials (ADR 0010), and concurrent startup is already serialised by ADR 0020's advisory lock. CONTEXT.md now distinguishes **instance** (one deployment = one organization) from **replica** (an interchangeable process sharing one pool). **ADR 0027 (SPEC §12.5, ROADMAP §3.8) adds the audit log of admin actions**: migration `0005.audit-log` (an insert-only `audit_log` table, no FKs, named CHECKs on `actor_kind` / `action`), `record_audit` / `list_audit` on the `Store` port, and `GET /v1/admin/audit-log` (admin-gated; no MCP verb). It has two write paths. `AccessService` (and `GovernanceService.withdraw`, only when an admin withdraws another agent's entry) writes `admin_key` rows **after** the mutation succeeds, not atomically, and **raises** if the audit write fails. The actor is `admin:<key fingerprint>`, via the new `Credential.key_id` (the first 12 hex chars of the stored key hash; every admin key shares `user_id = "admin"`, so this is what tells them apart). `hivemind-keys` writes `cli` rows **in the same transaction** as its change, under an **unverified** `--actor` (default: the OS user). No raw key ever reaches an audit column: the writers take no key argument, and a cross-path test searches every row for every issued key. Read-only calls are not audited; a new registration is (**ADR 0046**, migration `0009.audit-register`: action `agent.register`, actor kind `org_key` / `org:<fingerprint>` for the org key, detail `{owner_alias}`). **ADR 0028** gives agents a `revoked` status (migration `0006`; revoke from `pending` rejects a registration; `activate` works only from `pending`/`revoked`, so no agent ever holds two keys) and adds a `before` cursor to the audit log. **Migration `0008.history-and-list-indexes`** (`CONCURRENTLY`, `-- transactional: false`, the ADR 0025 pattern) adds a partial index on `entries.superseded_by`, one on `(created_at DESC, id DESC)` and one on `(author, created_at DESC, id DESC)`: the `?history` reverse walk is now one `Store.list_predecessors` query per hop instead of a scan of the whole pool (108 s on 200k rows), the default list order stops sorting the table, and `MetricsService` reads one grouped `Store.usage_counts` scan instead of 10 + 3×agents + fleets `COUNT`s. **ADR 0030** adds `hive_whoami` / `GET /v1/whoami` (the calling key's standing: kind, status, trust level, home fleet, `can_read`, `can_write_scopes`). **ADR 0031** corrects the docs to the code: one key per request, and rotating the org key closes registration without cutting off active agents. The agent plugin lives in `plugins/hivemind/` (Claude Code, Codex, DeepSeek Harness, Hermes, Pi, Oh My Pi and OpenCode, plus setup instructions for Gemini CLI). **ADR 0032** turns ADR 0024's startup failure on unknown `HIVEMIND_*` variables into a WARNING by default (GitLab Auto DevOps and Kubernetes service links inject prefixed variables Hivemind does not own); `HIVEMIND_STRICT_ENV=true` restores the failure, and the dev Makefile sets it. The shipped Deployments set `enableServiceLinks: false`. **ADR 0033** closes the `self`-isolation holes: every read by id (`hive_get`, `GET /v1/entries/{id}`), the supersession chain, feedback and withdrawal follow readability and answer not found for invisible entries (`services/chain.get_visible_entry`); MCP `hive_write` has no `author` parameter and an agent key's `agent` wins, as on REST; supersession requires a readable target and a successor that reaches at least the predecessor's audience (`domain.access.may_supersede`, enforced in `WriteService.write(..., writer=)`); `admin`/`org`/`dev`/`shared` are reserved agent names. **ADR 0039** makes the key lifecycle atomic: an agent key authenticates only while its agent is `active` (one joined query), issue/revoke are serialised per agent, migration `0007` adds unique indexes for one key per agent / one org key (deduping existing rows, newest wins), CLI `issue-agent` on a pending/revoked agent needs an explicit `--trust-level`/`--home-fleet`, re-registering a name answers with its status for the same alias and `name_conflict` for another, and pre-v2 `user` keys no longer verify. **ADR 0034** closes the double-supersession hole the state-guarded flip left: a `supersedes` target must be **active** — an already-superseded or withdrawn entry is rejected with the same `supersede_denied` (outranking the admin bypass), because `superseded_by` is single-valued and a second claim would be silently lost, orphaning the §6.3 ranking invariant; re-target the current head. **ADR 0029** adds the admin panel: `src/hivemind/admin/` (`hivemind-admin`, `HIVEMIND_RUNNER=admin`), a static no-build UI plus an allowlisted same-origin proxy to `hivemind-api`, deployed from its own kustomization (`deploy/kubernetes/admin/`); the admin key lives in the browser tab's `sessionStorage`, guarded by a strict CSP and text-only rendering. **ADR 0040** adds shared input bounds (`domain/validation.py`: no U+0000, size caps, `limit` ≤ 100 / `offset` ≤ 10 000, a 2 MiB REST body cap + 401-before-parse guard in `api/guards.py`) and the agent-name rules enforced in `AccessService.register` (since **ADR 0045** names are also unique ignoring case: `PgStore.register_agent` refuses a case variant under a per-folded-name advisory lock; existing collisions stay); the admin panel proxy re-quotes path segments. **The rest of the 2.0.0 review:** **ADR 0042** — `hivemind-mcp-pg` re-verifies its key on every tool call (a revocation or demotion applies to the next call), a missing per-request credential fails closed (`unauthenticated`), the MCP 401 carries `WWW-Authenticate` and `/.well-known/oauth-*` answers 404, and `HIVEMIND_MCP_ALLOWED_HOSTS` / `_ORIGINS` turn on the MCP SDK's Host/Origin check; supersession is atomic in the store (the guarded flip runs in the insert's transaction and raises `ports.SupersedeConflict`, mapped to `supersede_denied`), so concurrent writers cannot both supersede one head, and the write path runs the embedder and extractor concurrently; the pools register a `json`/`jsonb` codec (`payload` round-trips as a dict on Postgres) and bound every call (`HIVEMIND_POOL_COMMAND_TIMEOUT` / `_ACQUIRE_TIMEOUT` / `_CONNECT_TIMEOUT`; the server-side `statement_timeout` is opt-in because a transaction-mode PgBouncer rejects it), and `hivemind-migrate` refuses pgvector < 0.8 or a dim > 2000, checks the dim under the lock, fails on an INVALID HNSW index and reports a lost lock connection; the image installs from `uv.lock` (`uv sync --locked`) and runs as UID 10001 on a read-only root filesystem, the key bootstrap is a committed Job (`deploy/kubernetes/bootstrap/`, run by `scripts/ci-bootstrap-keys.sh`; since **ADR 0044** it runs `hivemind-keys bootstrap-secret` under its own narrow ServiceAccount and writes both keys straight into the `hivemind-keys` Secret, committing them only after the Secret exists, and never prints a key), `.github/dependabot.yml` bumps the base image and the GitHub Actions, and `tests/db_guard.py` refuses integration runs against a non-local or non-dev database (override: `HM_TEST_ALLOW_ANY_DB=1`). The review's open follow-ups are listed in ROADMAP §3.13. The unit suite is hermetic; the integration suite runs against dockerized Postgres and skips when it is down.

The *remaining* SPEC §11 open items are now settled as far as they can be without production data: **4.1 (BM25 vs. Postgres FTS) is DEFERRED** with the analysis recorded (no native BM25 in Postgres, so it is a custom-image / deployment-topology change; and RRF fuses *ranks*, so BM25's calibrated scores and IDF only ever reach the result through a better top-20 ordering — `ts_rank`'s missing IDF is the real thing it would buy), and **4.2 is rescoped** — the *how much / in what unit* half is closed by **ADR 0021** (the embedded-text body budget is 2000 whitespace-delimited words, `HIVEMIND_EMBEDDING_PREFIX_TOKENS`, and the knob now actually reaches the embedder — it was inert there, which also silently broke ADR 0016's lockstep invariant), leaving *what* goes into the embedded text open and chunking explicitly out of scope (SPEC §4.1 commits to one vector per entry). **4.6**'s cheap half is measured too (`tests/eval/test_rrf_k_experiment.py`): with decay on, sweeping `rrf_k` over {60, 20, 10, 5} does **not** recover the `old_exact` cases (0.000 hit@5 at every `k`) — the whole `rrf_k` lever is bounded at ~5.3 half-lives of age (`2(k+20)/(k+1)` < 40x) against entries 12.7–14 half-lives old — so `SearchConfig.rrf_k` was **not** changed. **4.6**'s other cheap lever came back **positive**: flooring the recency factor (`recency = max(floor, 0.5 ** (age/half_life))`) bounds the one unbounded factor in `entry_score`'s product, and a floor of 0.8 takes the `old_exact` slice from 0.000 to 1.000 MRR while holding `currency_pair` at 0.778 (above decay-off's 0.611) — the first variant to beat both extremes on the slice each is weak at. **ADR 0022 then shipped that floor on by default** (`SearchConfig.recency_floor = 0.8` + the matching `Settings`/`HIVEMIND_RECENCY_FLOOR` field, validated to `(0, 1]`; `entry_score`'s own parameter still defaults to `None` = the pre-0022 unbounded form) and amended SPEC §6.4's formula. The floor is a **band, not a slider** — 0.9 measures worse than decay-off, 1.0 *is* decay-off, so it must not be "tuned up" — and it is not free: `currency_pair` MRR 0.833 → 0.778, traded for `old_exact` 0.000 → 1.000. The §1.1 gate is bit-identical with and without it (the golden set is single-timestamp) and its thresholds were not re-pinned. That closes ROADMAP §4.6 (a) and rules out (b); per-kind half-lives stays held. Two config-hygiene follow-ups since then: **ADR 0023** gives `HIVEMIND_RECENCY_FLOOR` an explicit env spelling for "no floor" (empty string or `none`, case-insensitive), closing the gap ADR 0022 knowingly left (an operator reverting the floor no longer needs to approximate `None` with `1e-9`); **ADR 0024** makes `load_settings()` reject any `HIVEMIND_*` variable that is neither a `Settings` field nor on its `_ALLOWED_EXTRA_ENV_VARS` exemption list (`HIVEMIND_RUNNER`/`HOST`/`PORT`/`MCP_KEY`/`MCP_HTTP_PORT` — read directly via `os.environ` by code outside `Settings`), so a typo'd or renamed variable (as `HIVEMIND_EMBEDDING_PREFIX_CHARS` → `_PREFIX_TOKENS`, ADR 0021, now is) fails loudly at startup instead of silently no-opping; `Settings` itself keeps `extra="ignore"` so direct `Settings(...)` construction (tests, dev scripts) is unaffected.
