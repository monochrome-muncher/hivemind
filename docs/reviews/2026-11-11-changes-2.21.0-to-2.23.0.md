# Review of the changes from 2.21.0 to 2.23.0

Read on main at v2.23.0 (merge commit ca37748), compared with v2.21.0. It covers 2.22.0 (#377 automatic MCP Registry publish, #378 `hivemind-reextract`) and 2.23.0 (#380 to #388: the `hivemind-update` skill and drift check with fixes #381, #382 and #384, the Hermes install scan job #383, opt-in structured extraction output #385, two GitHub Actions bumps #386 and #387, and the `not_english` write warning #388).

**Result: no security issue, one bug, and small docs drift.** The bug is false `not_english` warnings on short English text with foreign-looking fragments. All findings are fixed in one pull request.

## Findings

| # | Severity | Where (v2.23.0) | Finding | Fix |
|---|---|---|---|---|
| 1 | Low (bug) | `src/hivemind/services/write_warnings.py:99-106` | `looks_non_english` counted function words inside identifiers and names. `[^\W\d_]+` splits `el9` into `el`, so "el8, el9 and el10 builds fail: rpm macros differ" drew the warning, and so did "Le Monde, El País, La Nación, Il Post: scrapers need new proxies". Both come from domains the evals cover (sysadmin, journalism), and ADR 0134 puts precision first. | A foreign function word counts only as a lower-case word of its own (not next to a digit, dot, hyphen or slash). Three new cases in `test_english_entries_are_not_flagged`, which all fail on v2.23.0. The non-English cases are still caught, and none of the repository's 4,078 Markdown paragraphs or the eval corpora draw the warning. ADR 0134 and SPEC §4.1 updated. |
| 1b | Low (bug) | `src/hivemind/services/write_warnings.py:101-102` (found after a question from the user) | The script test counted quoted text, so English that quotes a long Cyrillic error (`Error from 1C: 'Ошибка при выполнении операции: недостаточно прав доступа' on locked periods`) was flagged. Names given in several forms (`Zhang Wei (张伟, Chang Wei)`, `Дмитрий Иванов`, a full Chinese company name) were already fine: one CJK character counts as one letter, so Latin text outweighs them. | Quoted text (straight, curly, «», 「」, back quotes) is left out of the script count. Five new English cases with Chinese and Russian names and quotes. Entries written in Russian or Chinese are still caught. |
| 2 | Docs | `plugins/hivemind/README.md:169`, `skills/hivemind-setup/references/antigravity.md:42`, `plugins/hivemind/__init__.py:97` | Still say "both skills" after #380 added a third. | "the skills" / "every skill". |
| 3 | Docs | `plugins/hivemind/README.md:903` (Removing) | Does not mention `~/.config/hivemind/plugin-source`, which the update skill can now create. | Added to the list of things you may delete. |
| 4 | Docs | `docs/ops-runbook.md:1119`, `deploy/kubernetes/maintenance/reextract-job.yaml:57` | The example cutoff `2026-11-11` is the day 2.21.0 was released, not when an operator deployed it, so entries written in between would keep the old names. | The runbook asks for the time you deployed 2.21.0, and the Job's comment says to set your own date. A full rerun is safe either way. |

## What was checked and holds

| Area | Result |
|---|---|
| #381 security fixes in `hivemind-drift.sh` | Hold. Every git call that takes an address puts it after `--` (`:147`, `:189`, `:203`), so an address like `--upload-pack=…` is not read as an option. `GIT_TERMINAL_PROMPT=0` on each network call. Credentials are stripped before any URL is printed (`:110`, `:198`), even with a raw `@` in the password, and git's own stderr is dropped. |
| Drift check, other inputs | Addresses read with `--source-from` must look like `scheme://` or `git@`, so `ext::` cannot get in, and git refuses `ext::` by default anyway. `plugin-source` is the user's own file. The fetched release is only compared (`cmp`, `diff`, `sed`), never run. Temporary folder removed on exit. |
| Drift check, source order | `choose_repo` (`:156-186`) matches the order the skill (`SKILL.md`, "Where it looks"), DEVELOPING.md and ADR 0132 give. `marketplace_of` walks the right number of folders for `<plugins>/cache/<marketplace>/<plugin>/<version>`. |
| Update references (14 harnesses) | Each file's check command, update steps and copies agree with the plugin README's update table and "Updating by hand" list. KiloCode's `git:…@v<version>` and OpenCode's `git+…#v<version>` entries are reduced to the bare address by `addresses_in`. |
| `hivemind-reextract` (#378) | Writes only `entities`, `entity_names` and `entities_model`, inside one transaction per batch with `lock_timeout` 5 s. `entity_names` is built the same way as on a write (`pgstore/entries.py:268`). The update re-checks `redacted_at IS NULL`, so a redaction that lands between read and write wins. A batch where every extraction fails, or a lock error, stops before writing. All SQL takes values as parameters; the batch size is an `int`. The batch query has no `(created_at, id)` index and scans the table each batch: fine at today's pool size (about 1.2K entries), noted only. |
| Structured output (#385) | The fallback turns structured output off only after a plain retry succeeds, so a 400 for another reason (a too-long entry) does not disable it. With it on and a server that ignored the parameter, the object-shaped prompt is still used and a bare array is accepted. No change when the setting is off. |
| `mcp-registry` job (#377) | Runs only on `vX.Y.Z` tags without a suffix, after the image publish. Checks that `server.json` matches the tag before publishing, verifies the pinned `mcp-publisher` against its Sigstore bundle, logs in with OIDC, needs no secret, `persist-credentials: false`. |
| Hermes scan job (#383) | Fetches Hermes at a pinned commit and runs it with `python3 -I`, in a workflow whose token is read-only. |
| Actions bumps (#386, #387) | Pinned by full commit SHA, versions in comments. |
| `not_english` (#388), apart from finding 1 | Advisory only, every scope, also on `check: true`; listed in SPEC §4.1 and ADR 0077. No always-on text added (budget unchanged). |
| Release files | Thirteen version files and the CHANGELOG rows for 2.22.0 and 2.23.0 agree with what shipped. |
| Tests | Full suite green on v2.23.0 before the fixes, and again with them. |

## Not covered

Live harness runs: the update skill was checked live on ten harnesses in #382 and #384, and nothing in this range changed that since.
