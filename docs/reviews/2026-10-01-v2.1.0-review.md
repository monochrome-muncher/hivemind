# Hivemind security and performance review of v2.1.0 (2026-10-01)

> A review kept for reference. Findings, line numbers and PR states are as of the commit it names, so the code may have moved on. [SPEC.md](../../SPEC.md) defines behaviour and the [ADRs](../adr/README.md) record decisions.

Scope: what changed on `main` since this morning's review (PRs #22 to #32, `2af6245..ed86a25`): any-word keyword search (ADR 0047), keyword-only fallback (ADR 0048), registration audit and migration 0009 (ADR 0046), case-variant names (ADR 0045), store-timeout 503s, embedder vector checks, the bootstrap Secret writer (ADR 0044), ingress limits and the admin allowlist, egress policy, the migrate DSN, and the GitHub Tests workflow. This morning's findings (`2026-10-01-main-review.md`) are not repeated. Measured on Postgres 16 + pgvector 0.8.1 with a 100k-entry pool (120-word bodies, Zipf vocabulary).

## Findings, most severe first

### 1. Medium (DoS / performance): any-word keyword search lets one query burn seconds of database CPU. Fix: PR #33.
- `src/hivemind/store/pgstore.py:166` (main): `replace(plainto_tsquery(...)::text, ' & ', ' | ')` turns every query term into an OR branch, with no limit on how many.
- `src/hivemind/store/pgstore.py:634-643`: `ts_rank` then scores every matching row once per term. `src/hivemind/domain/validation.py:51` allows 2 000-character queries.
- Measured, keyword stream only (median of 3):

| Query | every term (2.0.x) | any term (2.1.0) | with PR #33 |
|---|---|---|---|
| 2 rare words | 0.7 ms | 1.8 ms | same |
| 5 words, one common | 0.9 ms | 225 ms | same |
| 2 000 chars of natural text | 6.7 ms | 2 136 ms | 542 ms |
| 300 common words (crafted) | n/a | 7 125 ms | ~550 ms |

- Any agent with read access can send the crafted query; a few at once hold Postgres's CPU. ADR 0047 said the worst case was unchanged (24 ms), but its table had short entries.
- Fix: match on the first 16 distinct terms (ADR 0049), built once per statement. Typical queries are unaffected; the golden-set gate still passes.
- Still open: one common term costs ~85 ms on 100k rows (linear in matches). That is ROADMAP §4.1 (BM25 / FTS), as before 2.1.0.

### 2. Low: `/v1/metrics` is admin-only but outside the new admin allowlist. Not fixed yet.
- `deploy/kubernetes/optional/ingress.yaml:86-105` restricts only the `/v1/admin` prefix; `GET /v1/metrics` (`src/hivemind/api/routes.py:130-137`, admin key required) is still served by the public `/` rule (`ingress.yaml:65`).
- Impact: an admin key can read usage counters from the internet. Small (counters only), but it contradicts the Ingress's own comment that admin REST is never reachable from outside.
- Proposed fix: add `/v1/metrics` (pathType Exact) to the `hivemind-admin-api` Ingress.
- Note for context: the allowlist limits key management, not admin keys in general. An admin key still reads everything and withdraws any entry via `/v1/search`, `/v1/entries` and `/mcp`.

### 3. Info: a registration whose audit write fails is never audited.
- `src/hivemind/services/access.py:161-178`: the agent row is committed first, then the audit row. If the audit insert fails (for example a pool timeout), the caller gets an error, and the retry takes the `already_registered` path, which writes no row. ADR 0027 accepts non-atomic admin audits; this is just the one case where a retry does not repair it. No change proposed.

## Checked and not an issue
- Any-term tsquery rewrite: no operator injection. Fuzzed with `& | ! <-> :* ( ) '` quotes, backslashes, URLs and hyphenated compounds; `plainto_tsquery` only ever emits quoted lexemes joined by `' & '`.
- Keyword-only fallback (ADR 0048): only `EmbeddingError` is absorbed; the embedder's overall deadline becomes `EmbeddingError` (`providers.py`), so it is not mistaken for a store timeout. Store failures still propagate.
- Store-timeout 503: provider calls never raise a bare `TimeoutError`, so the REST handler and MCP dispatch map only store timeouts.
- Case-variant names (ADR 0045): names are ASCII-only, so `lower()` is a correct fold; the per-name advisory lock serialises `Bob`/`bob` races. The folded lookup scans `agents` (no index on `lower(name)`), which is negligible at realistic agent counts.
- Migration 0009: widening CHECKs is additive; the rollback deletes only `agent.register`/`org_key` rows, as documented.
- Bootstrap Secret writer (ADR 0044): keys never reach a log or exception; the DB transaction commits only after the Secret exists; RBAC is create-secrets plus get/delete on `hivemind-keys`, removed after the Job.
- Egress policy placeholders fail closed; the Tests workflow uses `pull_request` (not `_target`) with `contents: read`.
